World Model Collapse on Out-of-Distribution Objects

We edit the first visual state of a recorded robot trajectory by replacing the manipulated object, then ask Ctrl-World to roll out the future under either recorded actions or a VLA policy. The page puts the two action sources side by side, with pickplace as the primary example.

Experimental setup

For each task, we keep the same starting trajectory identity and replace the object in the initial three-view observation. The edited initial states were generated with GPT Codex's imagegen image editing feature. The replay condition uses the original recorded action trajectory. The policy condition gives the edited observation and an object-aware prompt to the VLA policy, then rolls out the world model with policy-generated actions. Each video below has one shared reference row on top, followed by the baseline rollout and three edited-object rollouts.

Main comparison: pickplace

Pickplace is used as the main video because it makes the intervention easy to inspect: the object identity changes while the plate, arm, and table context should remain stable if the model handles edited initial states robustly.

Observed behavior

Object edits can destabilize the world model Replacing the manipulated object in the initial observation often leads to blurry or structurally inconsistent rollouts.
The failure appears in both replay and policy-in-loop Replay isolates the world model under recorded actions, while policy-in-loop tests the same edited initial state with actions generated by the policy.
Stable cases need a data audit Some edits remain coherent, possibly because similar objects or interactions already exist in Ctrl-World's training data.
